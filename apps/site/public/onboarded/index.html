02 / Forms & helpers

The simplification is in the helper.
TypeScript can have it, too.

Repeating a passport condition six times makes a form harder to maintain. Naming the shared condition removes that repetition in either language. A shorter translation is not, by itself, a reason to switch.

list-a-choice.tsIllustrative form DSL
const listAChoice = (
  statuses: ReadonlyArray<CitizenshipStatus>,
  selector: Path.Ref,
  doc: string,
) => Rule.any(...statuses.map((status) =>
  Rule.all(
    Rule.eq(p.citizenshipStatusCode, status),
    Rule.eq(p.employeeEnteredDocumentPath, "list_a"),
    Rule.eq(selector, doc),
  ),
));

// Reuse the condition wherever it is needed.
listAChoice(passportStatuses, listAType, "us_passport");

Rule and Path represent the form DSL in the supplied discussion; they are not exports of Open Ontology v0.1.

03 / Account configuration

Where Forma could
earn its place.

The interesting boundary is which facts configuration may read, who can author it, and how a workbench edits it. These are potential requirements, separate from making form code shorter.

Permission scopeDesign sketch · not enforced in v0.1

A rule can only read what its scope loads.

Switch the attribute a hypothetical access rule reads. A future scope checker could diagnose the unsupported read at its source location.

Proposed loaded facts:membership/role:membership/account
Within the proposed scope:membership/role is a loaded permission fact.

This browser demonstration compares attribute names. It is not the Forma compiler or an authorization check.

Scope as a check

02

Controlled authoring

A pure language could matter when customers or agents author configuration that you build and run. TypeScript builders can execute arbitrary code.

Requires a defined execution boundary
03

Machine editing

A lossless syntax tree could make workbench patches easier. Editing one field that uses a helper still means deciding whether to change or break the abstraction.

Requires a round-trip editing design
The practical choice

Refactor the forms in TypeScript. Preserve the generated snapshot. Revisit Forma for account configuration when scope checking, customer authoring, or UI round trips becomes a real requirement.
