An account program, end to end

A whole onboarding account.
One file, checked and played.

Attributes, forms, policies, automations, access, integrations, and the scenarios that prove them, written in nine verbs. The Northwind program on this page is parsed, checked with located errors, lowered to resources, and simulated day by day. Every result shown here comes from running it.

Tour the language ↓ Read northwind.account.lisp ↗

Illustrative and synthetic. Vocabulary informed directionally by supplied Onboarded schema and API context. The Forma reader parses the program; a TypeScript elaborator in this example checks, lowers, and simulates it. The resource shapes echo platform field names but are not production formats. Nothing calls Onboarded or deploys configuration.

    06 / Boundary

    What runs today,
    and what would come next.

    The account program is example code, separate from the package’s portable ontology IR. It shows the shape of an Onboarded prelude; it is not one yet.

    Runs in this repository
    • Forma reader parsing, with every check reported at a line and column
    • Type, vocabulary, fact-scope, permission-scope, and reference checks
    • Lowering to directional account, property, form, policy, automation, group, and integration resources
    • Three-state policy evaluation and a day-by-day scenario simulator with decision coverage
    Not built
    • Production resource formats or byte-identical snapshots of them
    • Planning against, or deploying to, a live Onboarded account
    • Form rendering, Liquid beyond simple variables, and runtime formula evaluation
    • Integration behavior, persistence, authorization, or an onboarded Forma prelude
    The direction

    Write the account once, prove it with scenarios, and let a prelude elaborate the same declarations to the platform’s own configuration.
