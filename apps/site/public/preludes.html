One import, a shared graph

GitHub brings Git with it.

(import "/github") loads /std/git automatically, once per model. All declarations share one namespace. Imports use bundled identifiers, without filesystem or network resolution.

02Understand the language

The compiler is
part of the source.

These three preludes support compiler bootstrap and elaboration. They are loaded by the Forma adapter, not imported into your model. Their pages explain the machinery with labeled source excerpts.

01

compiler.lisp

The meta layer: form descriptors, slots, identifiers, and compile-time hooks. Loaded during bootstrap, not a domain import.

Read the source guide →02

ontology-compiler.lisp

Bindings, validation, result types, and construction hooks referenced by ontology.lisp. Compiler implementation, not a modeling library.

Read the source guide →03

viewspec-compiler.lisp

A hosted ViewSpec layout-validation hook, loaded at bootstrap. View authoring and a UI runtime are not supported by this package’s Triplex adapter.

Read the source guide →

Current availability

What you can use today.

The six sources above are checked in and bundled with experimental v0.1. Clone the repository, use Node 24 and pnpm 10.11.0, and follow a library’s model-check instructions. There is no npm release yet.

Read the full source map ↗

Platform sketches are future work.

The homepage’s Salesforce, Stripe, Okta, GitHub teams, PagerDuty, and cross-project examples are v0.2 design sketches. They are not shipped libraries or commands. The available /github import models local metadata; it does not deploy or sync GitHub configuration.

No native deployment, platform synchronization, durable server, or oo package registry ships today.
