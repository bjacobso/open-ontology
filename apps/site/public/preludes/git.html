The pitch

A vocabulary to build on.

Use it when a release, build, or service needs to point at a precise commit, or when repository dependencies need to be queryable alongside your own domain facts.

What’s included

Objects
GitRepository, GitCommit, GitBranch
Relations
git-parent, git-fork-of, git-depends-on
Actions
Eight actions record repositories, commits, branches, parents, forks, and dependencies. Branch-tip and default-branch updates clear the old reference first.
Queries
git-branch-tips and git-repository-dependencies

Authoring example

Pin a release to a shared commit

This complete model adds Release to the imported graph. Record repository and commit facts with the bundled actions, then invoke record-release and query release-pins in the local runtime.

Save the complete model as examples/my-domain/model.lisp inside a repository clone, then check it: 

pnpm install --frozen-lockfile
pnpm model:check examples/my-domain/model.lisp

Use Node 24 and pnpm 10.11.0. Imports expand to ordinary declarations and share one namespace; imported types cannot be redefined. Only /std/git and /github are bundled import paths.

Run a checked-in scenario

The checked-in GitHub scenario exercises shared commits, merge parents, fork branches, and repository dependencies. 

pnpm example:github

Current availability

Available · experimental v0.1

Actions record local facts; they do not run Git commands. Callers supply ids. Full object ids and repository-scoped branch ids are conventions, not uniqueness guarantees. Reference existence, branch/repository consistency, and acyclic ancestry are not enforced.

Work in a clone; the package is not released on npm. Native platform deployment, synchronization, and the oo package manager are not available.
