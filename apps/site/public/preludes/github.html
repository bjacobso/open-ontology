The pitch

A vocabulary to build on.

Use it to describe engineering work alongside your operational model: who opened an issue, which fork a pull request comes from, or which issue a proposed change references.

What’s included

Objects
GitHubAccount, GitHubRepository, GitHubIssue, GitHubPullRequest
Relations
github-member-of, github-collaborator, github-references-issue
Actions
Seven actions record accounts, hosting records, issues, pull requests, memberships, collaborators, and issue references.
Queries
github-repositories, github-forks, github-pull-request-issues; plus the imported Git queries

Authoring example

Find open issues and their authors

This complete model adds a query to the bundled vocabulary. Populate it with git-create-repository, github-record-account, github-record-repository, and github-open-issue; then query open-issues-by-author.

Save the complete model as examples/my-domain/model.lisp inside a repository clone, then check it: 

pnpm install --frozen-lockfile
pnpm model:check examples/my-domain/model.lisp

Use Node 24 and pnpm 10.11.0. Imports expand to ordinary declarations and share one namespace; imported types cannot be redefined. Only /std/git and /github are bundled import paths.

Run a checked-in scenario

The checked-in scenario seeds synthetic local facts and runs cross-fork pull requests, issue references, collaborators, and dependencies. No credentials are needed. 

pnpm example:github

Current availability

Available · experimental v0.1

This is local metadata: no GitHub API calls, deployment, or synchronization. Membership roles and collaborator permissions are descriptive facts, not authorization. States and account kinds are strings, not enums. Teams, reviews, checks, and releases are not modeled. Issue references do not imply closure.

Work in a clone; the package is not released on npm. Native platform deployment, synchronization, and the oo package manager are not available.
