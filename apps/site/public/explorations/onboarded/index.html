Onboarded domain study

This is a selected, illustrative study informed directionally by supplied Onboarded schema and API context. The complete attachments stay in the workspace's private .context directory; the example contains hand-authored declarations and synthetic facts. The unlisted /onboarded site page presents both parts.

Northwind account program

northwind.account.lisp configures one synthetic account end to end in nine verbs:

Verb Declares
account Name (the key namespace), languages, sender and support emails, deduplication criteria
attributes Typed custom attributes on built-in entities, with closed choices and :searchable, :sensitive, :scope, :pattern, and :deprecated
rule, def Named three-valued predicates reused everywhere; build-time arithmetic
form Pages and fields that bind attributes or form answers; :from references another package's form
policy :when a placement matches, :require forms, optionally each with its own :when
automation, param A trigger, then wait, when, email, and assign steps; per-target parameters
group Permissions plus an access rule
integration A pinned provider revision and a connection reference
scenario Facts, then expect, record, and complete on day 0 and later (day n ...)

The Forma reader parses the file. The TypeScript elaborator in account/ is example code, not a Forma prelude or package export:

  • elaborate.ts resolves names and attribute paths; checks types and choice literals, field/attribute compatibility, deprecated writes, sensitive-attribute flags, policy and trigger fact scopes, :scope-only access rules, key namespaces, and due dates required by waits. Every problem is reported with a line and column, without cascading errors.
  • lower.ts lowers declarations to directional account, property, form-reference, form, parameter, policy, automation, user-group, integration, and scenario resources. Names map to platform snake_case, named rules are inlined where used, and def arithmetic folds into constants. The shapes echo platform field names but are not production formats.
  • evaluate.ts evaluates policies with three-valued logic: an unrecorded fact is unknown, and an unknown outcome names the facts it is waiting for. Scenarios play a placement forward day by day: policies assign tasks, task due dates come from :due-in, automations wait, decide, email (rendering simple {{ entity.field }} variables), and assign.
  • check.ts fails on elaboration errors, failing scenario expectations, and any policy or automation decision that no scenario sees both true and false.
  • mistakes.ts lists ten plausible edits; tests require each to produce exactly one located error.
pnpm account:check examples/onboarded/northwind.account.lisp
pnpm account:check examples/onboarded/northwind.account.lisp --json

Nothing here calls Onboarded, plans against or deploys to an account, renders forms, evaluates runtime formulas, runs integrations, or enforces access rules.

Domain ontology

The TypeScript model exports twenty object types, two demo actions, and three Datalog queries, explored in four graph views:

View Concepts and relationships
People & work Accounts, employees, employers, placements, and tasks; a task references a concrete template and can have a user as employer assignee.
Forms & versions A form lineage has versions; a concrete task template references its version and lineage; page templates contain fields.
Account & access Accounts belong to organizations; organization membership and user-group membership are distinct records.
Policy & scope Policies reference form lineages through policy forms; custom properties carry permission-scope flags; automations and inference rules describe account configuration.

Placements describe an employee's employment context, while tasks share employee/account/employer dimensions. There is no direct Task.placement reference in this model. Client/job-type dimensions, suggested tasks, runtime page/field submissions, files, external integrations, connected organizations, and distribution are omitted. An employee's name is reduced to one synthetic display field. Optional/shared configuration ownership is retained where useful, but this example does not reproduce the complete schema or API contracts.

pnpm model:check examples/onboarded/model.ts
pnpm example:onboarded

The local scenario seeds an example form lineage/version/template and creates a task. request-review replaces its next action and employer assignee; repeating it with another user leaves only the new assignee in the review queue. employee-input and employer-review are demo next-action values. The requires_action status remains unchanged. These actions exercise local Triplex mutations and queries, with no Onboarded API requests or production workflow semantics. User-group rules, policy rules, field rules, automation trigger descriptions, and authorization inference configuration are modeled as opaque data in this ontology.

Site artifacts

pnpm site:export-onboarded writes two browser artifacts. model.json holds the ontology IR, the runtime transcript, and the graph views from apps/site/onboarded-views.json, where diagram positions are defined and arrows come from reference properties. account.json holds the Northwind source, its lowered resources per declaration, the checker output, scenario timelines, decision coverage, each mistake's recorded diagnostic, and the policy evaluator's result for every combination of the simulator's facts. Tests verify that both artifacts match the checked-in sources.

; Northwind: one Onboarded account, end to end, in one file.
;
; Illustrative and synthetic. The Forma reader parses this file; the example's account
; elaborator checks it, lowers it to directional resource IR, and simulates its scenarios.
; Nothing here calls Onboarded or deploys configuration.
;
;   pnpm account:check examples/onboarded/northwind.account.lisp

(account northwind "Northwind Logistics"
  :languages [:en :es]
  :sender "onboarding@northwind.example"
  :support "people@northwind.example"
  :dedupe [employee.email])

; ── Attributes: built-in entities, extended with typed fields ────────────────────────────

(attributes client
  (region (one-of :west "West" :east "East") "Region" :scope)
  (requires-drug-screen boolean "Requires drug screen"))

(attributes job
  (site-type (one-of :warehouse "Warehouse" :office "Office") "Site type" :searchable)
  (hourly-rate decimal "Hourly rate"))

(attributes placement
  (union-local (one-of :local-42 "Local 42" :local-77 "Local 77" :none "Not represented")
    "Union local" :searchable)
  (weekly-hours integer "Scheduled weekly hours"))

(attributes employee
  (badge-number string "Badge number" :searchable :pattern "^NW-[0-9]{6}$")
  (union-card-number string "Union card number" :sensitive)
  (mailing-address address "Mailing address")
  (forklift-certified-on date "Forklift certification date")
  (legacy-hris-id string "Legacy HRIS ID" :deprecated "Replaced by badge-number"))

; ── Rules: named, three-valued, usable by policies, forms, automations, and access ───────

(rule at-warehouse (= job.site-type :warehouse))

(rule union-covered
  (and (not= placement.union-local :none)
       (>= placement.weekly-hours 20)))

(def dues-rate (/ 1.5 100))   ; build-time arithmetic, inlined as 0.015

; ── Forms: fields bind attributes or form answers; reads and writes are inferred ─────────

(form w4 :from "onboarded.compliance" :key "irs.w-4")

(form union-card "Union card"
  :due-in 30
  (page "Union membership" :employee
    (checkbox has-card "I already hold a union card" :es "Ya tengo una tarjeta sindical")
    (text employee.union-card-number "Union card number" :required :show-if has-card)
    (address employee.mailing-address "Mailing address" :required)
    (formula weekly-dues "Estimated weekly dues"
      (round (* job.hourly-rate placement.weekly-hours dues-rate) 2))
    (signature employee-signature))
  (page "Steward review" :employer
    (review [employee.union-card-number weekly-dues])
    (signature steward-signature)))

(form site-safety "Globex site safety" :key "northwind.globex.site-safety"
  (page "Site rules" :employee
    (checkbox acknowledged "I have read the Globex site safety rules" :required)
    (signature employee-signature)))

(form forklift-certification "Forklift certification"
  (page "Certification" :employee
    (date employee.forklift-certified-on "Certification date" :required)))

(form drug-screen-consent "Drug screen consent"
  (page "Consent" :employee
    (content "I consent to a pre-placement drug screen.")
    (signature consent-signature)))

; ── Policies: when a placement matches, require forms ────────────────────────────────────

(policy warehouse-onboarding "Warehouse onboarding"
  :when at-warehouse
  :require [w4 site-safety
            (drug-screen-consent :when client.requires-drug-screen)])

(policy union-card-obligation "Union card"
  :when union-covered
  :require [union-card])

; ── Automations: a trigger, then steps ───────────────────────────────────────────────────

(param overdue-template :sendgrid-template "Supplied per target account.")

(automation union-card-reminder "Union card reminder"
  :on (task-created union-card)
  (wait 2 :days :after task.due-at)
  (when (not= task.status :completed)
    (email :employee overdue-template "Your union card is overdue"
      "Hi {{ employee.first_name }}, please complete your union card.")))

(automation forklift-follow-up "Request forklift certification"
  :on (placement-created)
  (when (and at-warehouse (missing? employee.forklift-certified-on))
    (assign forklift-certification)))

; ── Access and integrations ──────────────────────────────────────────────────────────────

(group west-managers "West region managers"
  :can [:placement/read :employee/read :task/read :task/edit]
  :sees (= client.region :west))

(integration checkr "@onboarded-platform/checkr@1.4.0"
  :connection "checkr"
  :package "driver_pro"
  :adjudication :manual)

; ── Scenarios: facts in, outcomes out; every decision covered both ways ──────────────────

(scenario "warehouse, Local 42, full time"
  {job.site-type :warehouse placement.union-local :local-42
   placement.weekly-hours 32 client.requires-drug-screen false}
  (expect :policies [warehouse-onboarding union-card-obligation]
          :forms [w4 site-safety union-card]
          :tasks [w4 site-safety union-card forklift-certification]))

(scenario "certified driver, drug screen required"
  {job.site-type :warehouse placement.union-local :none
   client.requires-drug-screen true employee.forklift-certified-on "2026-03-14"}
  (expect :policies [warehouse-onboarding]
          :forms [w4 site-safety drug-screen-consent]
          :tasks [w4 site-safety drug-screen-consent]))

(scenario "office, not represented"
  {job.site-type :office placement.union-local :none}
  (expect :policies [] :forms [] :tasks []))

(scenario "union local recorded on day five"
  {job.site-type :office placement.weekly-hours 32}
  (expect :forms [] :unknown {union-card-obligation [placement.union-local]})
  (day 5 (record placement.union-local :local-42)
         (expect :policies [union-card-obligation] :tasks [union-card])))

(scenario "Ada returns her union card on day ten"
  {employee.first-name "Ada" job.site-type :office
   placement.union-local :local-42 placement.weekly-hours 32}
  (day 10 (complete union-card))
  (day 40 (expect :open [] :emails [])))

(scenario "Ben's union card goes overdue"
  {employee.first-name "Ben" job.site-type :office
   placement.union-local :local-77 placement.weekly-hours 24}
  (day 31 (expect :emails []))
  (day 32 (expect :open [union-card]
                  :emails [{:to :employee :body "Hi Ben, please complete your union card."}])))
