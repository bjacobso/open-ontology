# Foundry Ontology as Code

Experimental v0.1 compiler, best effort. A model written in Forma (or the TypeScript DSL) compiles to a TypeScript module for [`@osdk/maker`](https://www.npmjs.com/package/@osdk/maker), the source format of Palantir Foundry's Ontology as Code (beta). The same model still runs locally on Triplex.

```text
model.lisp ──> OntologyIR ──┬──> Triplex runtime (local actions and queries)
                            └──> compileOsdkMaker ──> @osdk/maker module ──> Foundry
```

```sh
pnpm model:foundry examples/support-desk/model.lisp --name support-desk --out ontology.ts
```

The command runs the model checker first; checker errors stop the compile. Anything the compiler approximates or leaves out prints as a warning on stderr and is repeated in the generated file's header. [The support-desk output](https://github.com/bjacobso/open-ontology/blob/main/examples/support-desk/foundry/ontology.ts) is checked in and regenerated by the test suite. From code, `compileOsdkMaker(ir)` returns `{ source, diagnostics }`; it is exported from the package root and from `@open-ontology/ontology/foundry`.

## Status

The tests compile the support-desk, field-service and GitHub models, type-check the output against `@osdk/maker` 0.79.0, and register it with maker's `defineOntology`. That proves maker accepts the module. It has not been installed into a Foundry enrollment. Ontology as Code is a Foundry beta, enabled per enrollment. The `@osdk/maker` API is pre-1.0 and the generated `defineAction` rules use its lower-level logic-rule types, so pin the maker version in the repository that consumes the output.

To use the output, put it in an Ontology as Code repository created from Ontology Manager; the maker CLI reads `.ontology/ontology.ts` by default. Maker prefixes object and action API names with the repository's namespace.

## Mapping

| Open Ontology | `@osdk/maker` output |
| --- | --- |
| `define-entity Ticket` | `defineObject` with API name `Ticket`, display names from the name, and the entity's `:doc` as its description |
| Object id | A synthesized `id` string primary key; `<entity>Id` if a field already compiles to `id` |
| First required `String` field | Title property; otherwise the first `String` field, then `id` |
| `String`, `Int`/`Float`/`Number`, `Bool`, `Instant` | `string`, `double`, `boolean`, `timestamp` |
| `Json` | `string` holding JSON text, with a warning |
| `(List T)` | `array: true` |
| Field `ticket/opened-at` | Property `openedAt`; the namespace is prepended if the name is reserved or taken |
| Reference field `ticket/customer Customer` | Foreign-key property `customerId` and a one-to-many link `ticket-customer`: `customer` from the ticket, `tickets` from the customer |
| Many-valued reference | Array of ids, with no link type and a warning |
| `define-relation` without fields | Many-to-many link with the relation's name: `assignedTo` forward, `assignedToWorkOrders` back |
| `define-relation` with fields | Link object `<Relation>Link` with `id`, `fromId`, `toId` and the fields; two one-to-many links; an intermediary link with the relation's name |
| `define-action` input | Action parameter. An input used as an object to modify, a link endpoint, or a reference value becomes an object reference; other inputs keep their scalar type |
| `create` | `addObjectRule`; later `set`s on the same input fold into it |
| `set`, `clear` | One `modifyObjectRule` per object parameter. `clear` then `set` becomes the `set`, because Foundry replaces values. A lone `clear` writes null |
| `link` | `addLinkRule` for a relation without fields; an `addObjectRule` on the link object, with a generated id, for a relation with fields |
| `now` | `currentTime` |
| Reference value from an object parameter | The referenced object's primary key |
| `define-datalog-query` | Not compiled; warning |

## Not compiled, or compiled differently

- Queries. Foundry has no Datalog equivalent; Functions or object set definitions would need hand-written code.
- Integer precision. The IR records `Int` as `number`, so every number becomes `double`.
- Writes to many-valued properties. Foundry replaces whole arrays, while `set` adds one value; such writes are omitted with a warning.
- `set` and `clear` on a fixed object id, and `link` changes whose endpoints are not existing objects passed as parameters (including an object created by the same action).
- Link history. Locally, relinking the same pair reuses one link id; in Foundry each `link` creates a new link object.
- Data sources, permissions, markings, interfaces, shared properties, value types, enums, icons and submission criteria. Maker's defaults apply. The current IR has no way to declare them.
- Required fields. They select the title property, but no nullability constraint is emitted.
- Import from Foundry and deployment. There is no reader for existing Foundry metadata, and nothing here calls Foundry.
